# BIOFIT DASH V6.4 experimental — BIOFIT Level Editor 1.0
Fecha: 25/11/2026. Base estable: V6.3, 597631a69eed15a064c96baa14759a06704d22ce. El usuario solicitó un editor completo exclusivo de Unity, edición de colisiones por vehículo, monedas, portales, pads y corrección de orientación inicial del Cube. No autorizó merge a main. No se ejecutó Unity en el entorno del asistente. No dar V6.4 por instalada ni validada hasta prueba del usuario.

## Arquitectura y uso
- BIOFIT > Level Editor > Abrir editor. EditorWindow IMGUI, bajo Assets/BIOFIT/GeomeTry/Editor y #if UNITY_EDITOR. No crea escenas, no duplica proyectos, no se incluye en APK. Se muestran objetos a partir de JSON, con sprites locales y coordenadas GD. El editor no carga el motor de juego ni BLE al editar.
- Elegir una de las cinco ranuras y Cargar / borrador. Catálogo estándar persistente, más plantillas detectadas de los cinco mapas y texturas PNG locales (38 frames referenciados en los mapas V6.3 originales reconstruidos). Buscar por nombre, tipo, ID, nombre de sprite; Colocar y click. Portal Cube/Ball/Spider, gravedad normal/invertida, pad amarillo/rosa/gravedad, orbe, moneda, sólidos, pinchos, decoración y eventos de color. Los enterEffect se conservan, no se ejecutan visualmente.
- Arrastrar, Shift multi-selección, caja en vacío, Alt+click para solapados, selección por índice/ID, Ctrl+A, C/V/D/Z/Y/S, Supr, flechas (Shift=1 GD), botón medio/derecho pan, rueda zoom, navegación por porcentaje y coordenadas, grilla 15/30/60 GD, giro/espejo/capas/orden, dimensiones hitbox y escala visual independientes. El overlay de colisión es una referencia rectangular, no la reproducción exacta de prefabs de pinchos/portales.
- Inspector: tipo, ID gráfico, X/Y, rotación GD, flip, tamaño, capa, orden, sprites por nombre, escala visual X/Y, rango vertical de portal, color/duración de trigger. Importar PNG propio/autorizado de forma local. No redistribuir atlas o texturas propietarias. Catálogo de recursos ya importados, no catálogo exhaustivo de todos los objetos de Geometry Dash 2.207.
- Colisión: 0 original; 1 decoración sin colisión; 2 plataforma sólida sin muerte lateral; 3 trigger rectangular letal al contacto; 4 plataforma y letalidad lateral/inferior según BiofitStereoSolidContact. Para 3/4, máscara Cube/invertido=1, Ball=2, Spider=4, Ship=8 (15 todos; 0 ninguno). Soporte layer 6. El filtro no cambia BLE ni física del avatar. Portales, pads/orbes/monedas conservan triggers propios. El motor actual permite 0–3 monedas en mapas editados; HUD se adapta. No habilitar Ship como portal nuevo sin petición.
- Vaciar borrador permite armar un nivel desde cero en una de las cinco ranuras, conservando nombre, música y manifest. Longitud editable entre 300 GD y longitud original de esa ranura; no crea un sexto slot ni extiende suelo/música. No cambiar Original.json ni Level.json.
- Guardar borrador escribe Builds/BiofitLevelEditor/{slot}/Draft.json y Base.json/Active.sha256 (local ignorado). Deshacer/rehacer hasta 60 cambios. Probar borrador guarda y prepara SessionState: abrir Main Menu original, Play y seleccionar la misma ranura. Solo bajo UNITY_EDITOR se lee Draft.json en vez de Active; al salir de Play se limpia. Aplicar al juego requiere confirmación y verifica Active contra huella conocida; escribe Active.json atómicamente y guarda PreviousActive.json puntual. Restaurar último Active recupera esa copia. Cancelar prueba preparada vuelve a Active. Conservar Base hasta exportar delta; Cargar activo (confirmado) reinicia borrador.
- FLM exporta PNG FULL escalado y tramos de hasta 4096 px usando sprites locales, rotación y flip. Render estático de referencia; colores iniciales, no efectos dinámicos/contornos de runtime; no simula colliders ni física. PNG se queda local hasta autorización.
- Exportar cambios crea tools/level_editor/changes/BIOFIT_level_{slot}_{fecha}_{hora}.json con base/target SHA-256, altas, bajas, campos modificados y orden de índices; no incluye Original.json, Active.json completo ni metadatos raw de objetos originales. Preserva campos desconocidos en el mapa local. level_delta.py reconstruye el JSON exacto desde una base coincidente, rechaza hashes incorrectos. Publicar delta experimental abre PowerShell con confirmación, verifica rama, origen y hashes, agrega exclusivamente delta e INDEX.md, commit y push sin force. Requiere Git y Python ya instalados y credenciales Git. Si falla push, revisar commit local; no afirmar publicación. No publica PNG nuevos automáticamente: si un delta depende de recursos locales nuevos, registrar y compartir por separado solo con licencia adecuada. Para un revisor, consultar INDEX.md y la cadena de hashes base/objetivo; aplicar deltas en orden a una base local coincidente.
- Prueba manual de delta: py -3 tools/level_editor/level_delta.py --proyecto <ruta> --delta <ruta JSON>. Agregar --aplicar con Unity cerrado solo si el Active tiene SHA base. Agregar --publicar solo para publicar delta/índice en niveles-mejorados (no en main).
- DIPL: cerrar Unity. Descargar paquete con instalador y VERSION.json (commit fijado); ejecutar py -3 instalar_v64.py --proyecto <ruta> --verificar y luego --instalar. Alternativamente script versionado tools/level_editor/instalar_v64.py con --commit <SHA aprobado>. El instalador usa git fetch + switch + merge --ff-only, no clona ni cambia .gitignore; verifica mapas V6.3, origen, ramas, árbol limpio y lista de rutas permitidas. Para regresar a V6.3 sin perder rama, --restaurar solamente si mapas todavía intactos; si hay mapas editados, restaurar PreviousActive/delta primero. No reset destructivo.

## Cambios de runtime mínimos
BiofitStereoLocalRuntime.Item añade collisionMode, deathMask y editorScaleX/Y; Data.editorRevision=1 identifica mapas editados. Los mapas sin editorRevision mantienen requisitos V6.3 (3 monedas, número de portales y endGD original). Mapas editados permiten 0–3 monedas y número variable de portales, meta acortable. BiofitEditedDeathZone aplica máscara por modo, BiofitStereoSolidContact conserva su comportamiento original con máscara 15. BiofitGeometryUX y BiofitV2Hud muestran el total de monedas. BiofitV63Outline preserva contornos originales y excluye objetos con colisión explícita, escala o sprite distinto. BiofitThreeModes inicializa la referencia real al SpriteRenderer de Character, endereza solo su rotación al aparecer y durante asentamiento inicial en Cube; tras primer salto/asentamiento termina corrección. No modifica Rigidbody2D, colliders, velocidad, gravedad, fuerza/velocidad de salto, rate de rotación de saltos, firmware, detector, cooldown ni submódulo. C# Editor y prueba SessionState se excluyen del player con UNITY_EDITOR. El runtime sí incorpora soporte para mapas editados, necesario para que sus colisiones funcionen en APK.

Se reconstruyeron cinco mapas del RAR con importador V5 y transformaciones V6/V6.2/V6.3. Los 5 SHA-256 compactos coinciden con MANIFIESTO_LOCAL_V63.json. Se ensayó reconstrucción de delta con alta/baja/edición en cada mapa y rechazo de hash incorrecto, conservación de raw. El instalador y publicación se ensayaron sobre repositorio Git temporal con archivos de prueba y mapas reales; preflight, FF, vuelta a main y publicación selectiva OK. No es una compilación Unity ni prueba de UI/colisiones, orientación, Play Mode, APK, BLE físico. Estado experimental pendiente de prueba del usuario. No prometer la corrección visual como confirmada hasta ver su resultado. No modificar mapas actuales durante instalación; no subir material original.
